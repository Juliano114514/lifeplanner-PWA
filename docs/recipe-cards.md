# 共享菜谱与直接删除

## 数据契约

- 菜谱使用独立 `Recipe`：`id`、`name`、`ingredients`、`seasonings`、`steps`，以及创建／修改信息和可选 `deletedAt`。材料项包含 `name` 和 `amount`；无用量时存空字符串。做法为有序文本数组。
- 菜名最多 200 字，材料名及用量最多各 100 字，每组最多 100 项；步骤最多 100 步、每步最多 10000 字。菜谱草稿最多 60000 UTF-8 字节，为 64 KiB 命令请求预留空间。材料和步骤允许空数组，已添加项必须填写名称或正文。同组材料名忽略空白和大小写后不能重复。
- 仍使用 `/api/v1/planner/commands` 的 `saveRecipe`、`deleteRecipe`，共享版本、操作 ID、IndexedDB 队列和冲突机制保持不变。两位成员都能编辑或删除。
- 菜谱保存携带打开编辑窗口时的聚合版本；后台同步到新内容后，旧编辑稿仍需经过版本冲突处理，不能静默覆盖。旧操作回执不能使本机已知版本倒退。
- 旧 `saveRecipe` 仍按原愿望格式解析以保持请求指纹一致，执行时只新增／更新名称，保留已存在的新材料和步骤。旧 `recipePin`、`recipeStatus`、`archiveRecipe` 确认后不改变内容或修改时间，但仍占用一次聚合版本。已删除目标拒绝所有修改。
- 旧基础快照、待同步预览、冲突快照及历史操作回执统一转换为新结构；历史回执不重写。无效命令转为可处理的冲突，原队列保留，不能用旧快照覆盖删除标记。
- 任务继续走独立任务版本协议。删除时保留删除标记与实例数据，所有列表及循环生成排除该任务。日程通过该标记解除有效关联，保存日程时前后端均清除关联字段。

## 我想吃与谁想吃

- 搜索旁切换「全部菜谱 / 谁想吃」，切换保留搜索条件；窄屏换行显示。两个列表共用菜名、食材、调味料匹配规则以及同一菜谱卡片和详情弹窗。独立操作按钮不会触发详情。
- 全部菜谱中的「我想吃」只加入本人，已加入后显示「已想吃 · 取消」。谁想吃显示参与者最新头像、原菜谱卡片和“吃到了”勾选框，缺少头像时显示名字首字。
- `PlannerData.recipeRequests` 存放 `{ id, recipeId, requesterIds, createdAt, completedAt }`，空的 `completedAt` 表示待吃。新命令是 `wantRecipe(recipeId, requestId)`、`cancelRecipeWant(requestId)`、`setRecipeEaten(requestId, eaten)`，参与者由登录身份确定，不能提交任意成员 ID。
- 同一道菜最多一轮待吃，两人合并头像；重复加入不增加参与者、不刷新本轮创建时间。取消只移除本人，最后一人取消后移除本轮。两人均可勾选或撤销，勾选对本轮全部参与者生效。
- 吃过再想吃创建新 ID。撤销已吃时恢复原参与者；已有同菜待吃轮次时合并到现有轮次并移除旧记录。已取消、合并或淘汰的 ID 不能通过状态命令重新创建。
- 待吃按创建时间倒序，已吃按完成时间倒序，相同时间按 ID 排序。客户端与服务端都保留所有待吃及最近 10 条已吃，裁剪发生在搜索之前，不影响菜谱本身。超出 10 条的历史不会因撤销其他条目而补回。
- 编辑菜谱后所有关联卡片读取最新内容；删除菜谱会同时移除其请求记录。离线预览失败不从旧快照恢复过期轮次，冲突时展示云端请求状态并保留原队列供处理。
- 冲突重放并发新建的同菜轮次时，后续队列命令会改用合并后的轮次 ID；请求体仍按现有操作 ID／指纹协议去重，不修改已发送命令。
- 增量迁移 `0010_recipe_requests.sql` 只在集合缺失时初始化空数组，同时提升表与 JSON 版本；重复执行保留已有记录。旧缓存和历史回执的缺失集合视为空，不把旧菜谱完成状态转换为想吃记录。

## 迁移与发布

1. 获得生产操作授权后备份 D1，保存备份路径及当前 Worker 版本。迁移期间暂停编辑，前端和 Worker 配套发布。
2. 按现有迁移链应用 `0009_recipe_cards.sql`。迁移只修改 `planner_state` 中的菜谱，保留 ID、名称、创建／修改信息和删除标记；移除归属、预算、地址、备注、状态、置顶、归档及完成历史。
3. 旧菜谱材料与做法初始化为空；如果已有新格式字段则保留。迁移将 `recipeFormatVersion` 设为 2，并同时增加表版本和 JSON 内版本。版本标记达到 2 时不重复转换。
4. 接着应用 `0010_recipe_requests.sql`。核对菜谱 ID／名称和数量、删除标记、材料及步骤不变、请求集合初始化和版本一致，再发布配套 Worker／前端。旧客户端应刷新后使用新菜谱页；旧离线队列可通过新客户端继续同步。
5. 升级前的未同步操作可能触发版本冲突。采用云端会放弃本机队列；重放本机修改基于云端新版执行，已删除目标仍被拒绝。不要清空浏览器存储来处理冲突。
6. 生产迁移或发布失败时停止后续步骤。移除的业务字段只能从备份恢复；恢复需要同时协调数据库和应用版本，并避免覆盖发布后新增内容，不直接回滚旧 Worker 操作新格式数据。

## 验收清单

- 未完成、已完成、归档任务／愿望可确认删除，取消不产生修改；循环删除明确作用于整个系列，归档长按仍可用。
- 删除后任务在首页、个人资料和任务页消失，不再自动生成实例；关联日程保留，能够独立修改、完成和删除。
- 菜谱仅名称可保存；旧归档菜谱可见，旧删除记录不可见，原愿望内容不变。
- 材料名称建议按食材／调味料分别生成，用量不自动套用；同组重复名报错，材料可修改和移除。
- 步骤可增删与上下移动；未保存时关闭弹窗、取消或刷新页面的确认有效。
- 手机和桌面检查长菜名、长 tag、大量 tag；卡片每组最多两行并显示剩余数量，详情展示完整材料和做法。
- 菜名、材料名、大小写及跨字段多关键词搜索正确；清空搜索不修改数据。
- 想吃：单人加入、两人合并头像、重复点击、取消本人／最后一人、任何成员勾选及撤销、新开一轮、撤销时合并、第 11 条已吃记录淘汰且待吃不受影响。
- 两个 tab 在搜索、窄屏、大量 tag 场景下正常显示；点击卡片打开详情，想吃按钮／勾选框不会误开详情；菜谱修改和删除联动正确。
- 离线连续加入／勾选及双端并发合并后，后续命令仍针对正确轮次；旧状态命令不恢复取消、合并或淘汰记录，更新后原材料及步骤不丢失。
- 断网保存／删除进入队列，重连同步；两端并发编辑、编辑与删除冲突、旧命令重放不能复活删除记录或清空新菜谱内容。
- 重复运行迁移不清空新内容，表版本与 JSON 版本一致；本地静态检查、迁移核验和真实登录双端验收分别记录。
