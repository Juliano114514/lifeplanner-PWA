# 愿望与地点搜索

愿望位于日程之后，分为想要去、想要吃、想要买。四个时间档位是固定意愿标签，不计算截止日期。预算为可选人民币金额，零表示零预算；留空表示预算未定。愿望归属两个共享成员之一，支持转交、置顶、完成/恢复和归档，完成/恢复记录保存在愿望中。

## 数据与接口

- `PlannerData.wishes` 随现有 `/api/v1/planner/snapshot` 返回；旧快照缺少集合时补为空数组，不提升业务版本。
- `/api/v1/planner/commands` 新增 `saveWish`、`wishPin`、`wishStatus`、`archiveWish`；沿用共享版本冲突、mutationId 幂等和离线队列。
- `POST /api/v1/places/search` 接收 `{ "query": "城市或公开地点" }`，返回 `{ "places": [{ "address": "…", "latitude": 0, "longitude": 0 }] }`，最多五项。需要登录、同源以及 `X-LifePlanner-Actor` 请求头；不记录查询原文到日志。
- 搜索只由用户点击或按 Enter 触发，不做自动补全、后台搜索或定位。手填地址不会发往地图供应商；修改已选地址会清除坐标。

## 上线配置

上线前先应用 `0006_place_search.sql`，再发布前端和 Worker。迁移只新增搜索锁、缓存表和容量限制触发器，不修改用户愿望或其他生活数据。

`PLACE_SEARCH_ENABLED=true` 启用搜索，设为 `false` 可关闭；`PLACE_SEARCH_URL` 为服务端可切换的 HTTPS Nominatim 兼容搜索端点，默认 `https://nominatim.openstreetmap.org/search`。替代端点应支持 `q`、`format=jsonv2`、`limit=5`、`accept-language` 参数及对应结果格式。此配置不要求更新已安装的 PWA。

公共服务不要求 API 密钥。全应用通过 D1 原子锁串行访问上游，请求结束后至少间隔一秒；锁异常中断后 30 秒过期。成功响应（包括空结果）缓存 24 小时，最多 100 项；错误不缓存、不自动重试。数据库或上游不可用时仍可手填并保存愿望。

公共服务有覆盖和可用性限制，使用时应遵守 [Nominatim 使用政策](https://operations.osmfoundation.org/policies/nominatim/)，保留 OpenStreetMap 署名，不提交私人住址等敏感信息。API URL 只能由服务端配置，不接受客户端指定上游。

## 待执行的运行验收

以下是验收清单，不表示已经通过自动化或设备测试：

- 三个入口及手机六项导航；长名称、长地址、头像缺失、空清单、已完成和归档展示。
- 新增、编辑、跨分类修改、转交、置顶、完成/恢复；预算为空、零、两位小数，负数和超精度被拒绝。
- 断网保存、重连同步、两端并发冲突处理；旧快照、旧待同步命令和冲突预览可以读取，旧命令不丢失愿望。
- 重试同一 mutationId 不追加记录；已经完成的愿望再次设置完成不追加记录。
- 搜索成功、空结果、限流、上游错误、关闭搜索和缺少迁移时的手填保存；修改查询或关闭弹窗后忽略旧响应。
- 两位成员并发搜索的原子限流、24 小时缓存过期、超过 100 个不同查询后的容量上限。

日历导出不在本次功能内。代码交付不自动执行远程迁移或部署。
